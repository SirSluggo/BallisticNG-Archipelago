# Contributing and local checks

Read AI-DISCLOSURE.md, docs/ARCHITECTURE.md and docs/KNOWN-ISSUES.md before changing the implementation. Describe AI assistance honestly in contributions. Existing code provenance is not a claim of review or correctness.

## Setup

Python 3.11 or newer is required. From the repository root, create/activate a development virtual environment if desired, then install requirements.txt. Run:

```text
python tools/run_tests.py
python tools/build_release.py
```

The Python tests use fixtures, not a live game or player saves. The installed copies under BallisticNGArchipelago/PanelRuntime must match the root modules. The builder checks that parity, manifest copies, the C# catalog digest, and the bundled Harmony hash. It rebuilds the apworld and compares shared source bytes in the player/source ZIPs.

Native C# compilation uses the owner's BallisticNG installation. Do not add game assemblies or decompiled game source to this repository. AP world audits require a separately obtained compatible Archipelago checkout and its dependencies; audit_templates.py checks option ordering, and audit_ap_fill.py accepts the repository directory plus an optional seed count.

## Change validation

- World changes: test generation and reachability, including medal tiers, starting inventory and all three finale gates. Keep runtime gates consistent with generator logic.
- Client/state changes: test disconnect/reconnect, history conflicts, pending checks, trap acknowledgments and refusal paths.
- Save changes: test with backups; verify normal/AP isolation, seed switching, restart, offline normal return and interrupted exit. Do not experiment on another person's only save.
- Menu/race changes: test entering/exiting scenes, custom ships, and restoration of temporary effects. Keep the open idle-demo crash in mind.
- Packaging: rebuild from source, inspect archive contents and verify that local state is excluded.

Record exact versions, steps and outcomes. A Python pass or syntax parser does not substitute for native gameplay testing. Avoid broad unrelated formatting changes when fixing a small issue.

## Repository hygiene

Do not commit dist/, .venv, logs, Data/Logs/Cache contents, server connection settings, room passwords, seed history, game saves or crash dumps. The release builder includes source and explicitly allowed assets; a working game installation is not a source checkout.

The bundled BallisticNG.yaml is generated by Archipelago rather than maintained separately. With a compatible Archipelago checkout and its dependencies installed, run `python tools/generate_template.py --ap-source PATH_TO_ARCHIPELAGO` to refresh it, or add `--check` to verify exact parity. Run this after option-description or default changes. The release builder also checks custom-option descriptions/defaults against options.py without needing an AP checkout.
